# PassWisely 1.2.5

- Login, registration and password-reset views have window controls: macOS traffic lights on the left; Windows minimize, maximize/restore and quit on the right.
- Login windows expose Dock/taskbar access and can be restored after minimization. The floating signed-in toolbar keeps its existing behavior.
- Queue and solution Settings both include a separate Quit action. Long settings panels scroll so the action remains reachable on smaller screens.
- Closing through the title-bar button or Quit ends the application; signing out remains a separate action.

## Validation

- Renderer and Electron TypeScript builds pass.
- Five existing desktop transport/processing regression tests and the OSS download-map test pass.
- Real Electron on macOS, isolated temporary account storage: login rendering, maximize to the display work area, exact original-bounds restoration, minimize, Dock activation restoration and Settings Quit verified.
- Windows renderer layout and control IPC verified on macOS using a Windows platform stub. Native Windows execution is not covered by that check.
- No real account or paid AI request is used by the window-control smoke tests.

## Release

Artifacts are built in `release/1.2.5` and published under the OSS prefix `releases/v1.2.5`. Both macOS architectures require Developer ID signing, notarization and stapling before upload.

Website buttons use `/api/track-download/*`. To update the legacy Nginx `/api/download/*` redirects after upload, run `sudo bash website/scripts/activate-downloads-1.2.5.sh` on wise. The script preserves the current TLS and other Nginx configuration and checks it before reload.
